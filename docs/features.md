## 10. 管理端功能

管理端分两种视角：**产品级平台**（`adminsystem.<根域名>`）与**租户级管理端**（`<租户编码>.<根域名>`）。同一套前端按作用域与权限渲染菜单。

| 模块                | 能力                                                                                                                                          |
|---------------------|-----------------------------------------------------------------------------------------------------------------------------------------------|
| 登录                | 账号密码登录、本地作用域切换（回环主机用下拉框/`?tenant=`，子域名主机跳转对应域名；部署环境仅域名）、环境与解析来源标识、锁定提示、登录后回跳、首次登录强制改密 |
| 会话                | Access Token 只存内存、自动刷新、跨标签页同步、退出时通知后端撤销                                                                               |
| 应用管理（产品级）  | 产品级平台维护应用（平台统一发布，租户通过市场开通）；新建时选择应用类型（工作流应用 / 对话应用 / 智能体）；支持搜索、状态筛选、分页、编辑、启用/停用、删除；租户视角只读展示「我的应用」（已开通实例） |
| 画布编排            | 三区布局：左侧资源与节点库、中间画布、右侧节点配置抽屉；拖拽节点、连线、缩放、小地图、对齐辅助线、撤销/重做、自动保存；节点覆盖开始/结束、大模型、Agent 循环、HTTP、插件调用、代码、知识库检索/写入、文本处理、JSON 序列化/解析、条件分支、循环、批处理、子工作流、设置变量、变量合并、人工审批、会话类节点、便签/注释（节点类型与 coze 数字编码对齐） |
| 调试与运行          | 整图 SSE 试运行（节点实时高亮 + 日志面板 + 输入/输出/耗时/用量）、单节点试运行、变量引用抽屉、运行历史与 checkpoint 断点续跑                     |
| 版本与发布          | 草稿自动保存；校验（环检测 / 多 Start / 变量类型）通过后发布生成不可变图版本；版本历史可回滚；租户可钉住版本；上架/下架、启用/停用                 |
| 应用市场            | 平台应用上架后，租户浏览并自助开通；开通生成 `tenant_application_instance`（授权方式、配额、有效期、钉住版本）                                  |
| 运行历史            | 按应用查看运行记录：运行中 / 成功 / 失败 / 待人审；查看节点级耗时与用量；支持恢复、fork、checkpoint 查看、Webhook 订阅                         |
| 资源管理            | 工具、Prompt、技能、知识四类资源统一管理，按平台 / 租户归属；支持版本、启停、废弃标记，以及在资源抽屉内按租户授权/撤销                                 |
| 模型配置            | 平台维护模型供应商（`model_provider`）与模型目录（`model_catalog`）；租户可在设置页选择默认模型，画布节点从可用模型目录中选择 |
| 用户授权            | 独立菜单按用户维护角色与管理单元（数据范围）；支持批量授权（单次最多 200 个用户）、关键字搜索与分页；数据来自 `users` + `user_roles` + `user_mgmt_unit_grants` |
| 角色管理            | 平台/租户各自维护角色增删改与复制；详情页按权限目录维护功能权限；系统角色不可删除、不可停用；平台角色可授权平台级资源（`button:role:*`）         |
| 用户管理            | 租户管理员与普通用户统一账号：增删改、多角色绑定、重置密码、启停（`button:user:*`）；列表展示「当前部门」（来自当前任职），支持按部门（含下级）筛选 |
| 部门管理            | 租户内部门树增删改查、层级（最多 10 级）、编码、排序、启停切换；删除时若存在子部门/任职记录则禁止（409 引导停用）；停用部门不可再挂接任职        |
| 任职管理            | 用户任职记录增删改查、按用户/部门/状态筛选；同一用户同时仅一条当前任职；调岗自动归档旧记录并写入新记录；支持结束任职、查看完整历史              |
| 管理单元            | 跨部门 / 跨人员的数据范围维护，可将若干部门与人员组合成管理单元并授权用户                                                                      |
| 应用配置-基础信息   | 租户应用可选「所属部门」（TreeSelect），平台应用该字段隐藏且强制为 NULL；同租户与启用校验                                                       |
| 管理员账号          | 平台维护产品级账号，租户维护拥有管理角色的用户；列表、创建、角色/状态调整、重置密码、删除（`button:admin-user:*`）                              |
| 租户管理            | 租户列表、新建、编辑名称与启用状态、租户设置（默认模型等）（`button:tenant:*`，仅产品级平台角色可授予）                                          |
| 审计日志            | 按操作人/动作/时间筛选审计记录，支持清空（`button:audit:clear`）                                                                               |
| 菜单与路由          | 菜单由 `/admin/context` 的 `menus`（`menu:*`）驱动，路由由 `page:*` 权限守卫；无权限路由返回 404                                               |
| 多租户标识          | 产品级资源显示「平台级」，租户内部只读；租户自有资源显示「本租户」                                                                             |
| 健壮性              | 路由懒加载、错误边界、404 页面、请求超时与重试                                                                                                 |

菜单由 `/admin/context` 返回的 `menus` 驱动，来源是角色拥有的 `menu:*` 权限。`departments`、`employments`、`mgmt-units` 在前端合并为「组织架构」SubMenu；`grants`、`users`、组织架构与租户管理按作用域收窄（租户专属 / 产品级专属）。自定义角色按实际授权显示，无权限路由返回 404。

授权管理页同样按视角收敛：平台只列平台级资源，租户只列本租户自有资源；列表展示授权汇总与授权状态，翻页保留勾选（单次最多 100 个），可批量追加/覆盖/移除。行内「配置授权」抽屉按租户配置访问范围（平台为「该租户不可见 / 整个租户 / 指定角色」，租户为「全部角色可见（默认）/ 指定角色」），保存只写入当前租户并刷新汇总。

### 画布编排 5 分钟上手

**应用就是一张画布。** 它是一张 DAG 图（或 Agent Loop），由节点和连线拼出来：

```text
   ┌─────────┐      ┌─────────┐      ┌──────────┐      ┌─────────┐
   │ 开始    │─────►│ 大模型  │─────►│ HTTP/插件│─────►│ 结束    │
   │ 收 query│      │ 改写意图│      │ 查外部API│      │ 组装答案│
   └─────────┘      └────┬────┘      └────┬─────┘      └─────────┘
        │               │  ▲              │
        │               │  └── RAG 命中文档（可选开关）
        │               ▼
        │        ┌─────────────┐
        └───────►│ 知识库检索   │
                 └─────────────┘

   节点状态机：pending ──► running ──► success
                              │
                              └────► error（整图 fail，画布染红）
```

**执行时序图（一次用户请求）：**

```text
 用户端      FastAPI     GraphRunner     LLMClient      ToolGateway     租户工具
   │           │              │               │               │              │
   │ POST /run │              │               │               │              │
   │──────────►│              │               │               │              │
   │           │ invoke()    │               │               │              │
   │           │─────────────►│               │               │              │
   │           │              │ Start 节点返回 inputs         │              │
   │           │              │               │               │              │
   │           │              │ LLM 节点：渲染 prompt        │              │
   │           │              │──────────────►│               │              │
   │           │              │               │ (RAG 开关开则先查向量库)      │
   │           │              │◄──────────────│ output        │              │
   │           │              │               │               │              │
   │           │              │ HTTP/插件节点：│               │              │
   │           │              │──────────────────────────────►│              │
   │           │              │               │               │ ① SSRF 校验  │
   │           │              │               │               │ ② 熔断检查   │
   │           │              │               │               │ ③ 限流检查   │
   │           │              │               │               │ ④ 重试循环   │
   │           │              │               │               │─────────────►│
   │           │              │               │               │◄─────────────│
   │           │              │◄──────────────────────────────│ 8KB 裁剪     │
   │           │              │               │               │              │
   │           │              │ End 节点渲染输出模板        │              │
   │           │◄─────────────│ outputs + 节点状态 + usage  │              │
   │◄──────────│              │               │               │              │
```

不写一行代码，在画布上拖出一个「query → LLM 改写 → 查工具 → 返回答案」的流水线：

1. 左侧菜单点「应用管理」→「新建应用」→ 选择应用类型（工作流应用 / 对话应用 / 智能体）。
2. 进入 `/apps/:id/edit` 画布，按模板自动生成骨架（空白画布自动生成 `开始 → 大模型 → 结束`）。
3. 点中间的大模型节点，右侧抽屉弹出配置：
   - **模型**：从平台可用模型目录中选择（未配置时可回退到 `.env` 的默认模型）。
   - **System Prompt**：写人设，比如 `你是一个帮助客服总结问题的助手`。
   - **User Prompt**：默认 `{{query}}`，把开始节点收到的 query 原样传给 LLM。
   - **Temperature**：0.7 就好。
   - **启用知识库检索**：打开开关 → 勾选已经 ingest 完成的知识资源（状态为 ready 的）。
4. 加节点：点底部浮条「+ 添加节点」，或从节点输出端口拖线到空白处弹出节点面板。节点按控制 / AI / 逻辑 / 数据 / 会话 / 杂项分组，覆盖开始、结束、大模型、Agent 循环、HTTP 请求、插件调用、代码、知识库检索/写入、文本处理、JSON 序列化/解析、条件分支、循环、批处理、子工作流、设置变量、变量合并、人工审批、会话类节点、便签/注释。
5. 点 HTTP 或插件调用节点：右侧抽屉选择已注册工具（只列本租户可用的），参数模板填 JSON，比如 `{"q":"{{llm_1.output}}"}`（把上一个 LLM 节点的输出当参数）。
6. 点结束节点：输出模板填 `{"answer":"{{llm_1.output}}"}` 或 `{"answer":"{{http_1.output}}"}`，决定最终返回给用户什么字段。
7. 左上角状态栏自动显示「保存中 / 已保存」，也可 `Ctrl/Cmd + S` 手动保存；「校验」入口会列出图结构问题（环、多 Start、变量类型不匹配等）。
8. 点底部「试运行」→ 输入启动参数（比如 `查询北京天气`）→ 画布节点逐个点亮：
   - 🟡 黄色脉冲 = 运行中
   - 🟢 绿色边框 = 成功（右侧调试面板可展开输入/输出/耗时/用量）
   - 🔴 红色边框 = 失败（显示错误分类）
   也可以只对当前节点做单节点试运行，不写运行历史。
9. 校验无 error 后点右上角「🚀 发布」→ 生成不可变图版本 `vN`；后续改草稿不影响线上，可在版本历史里回滚，租户可钉住某个版本。
10. 发布后到「应用市场」上架，租户即可自助开通并使用。

> **模板变量怎么写？**
> - `{{query}}` = 开始节点收到的全局入参
> - `{{llm_1.output}}` = 节点 ID 为 `llm_1` 的大模型节点输出
> - `{{http_1.output}}` = 节点 ID 为 `http_1` 的 HTTP 节点输出
> - 节点 ID 在抽屉顶部可见；「变量引用」抽屉可浏览所有上游节点可引用的字段。
>
> **快捷键**：`Ctrl/Cmd + Z` 撤销、`Ctrl/Cmd + Shift + Z` 重做、`Ctrl/Cmd + Enter` 试运行。

### 工具接入 5 分钟上手

**所有 HTTP 工具调用都必须经过这道治理关卡：**

```text
                invoke_http(url, method, headers, body)
                            │
                            ▼
              ┌─────────────────────────────┐
              │ ① SSRF 校验                  │
              │   ├─ scheme 必须 http/https  │
              │   ├─ DNS 解析所有 IP          │
              │   └─ 拒绝 loopback/云元数据/  │
              │      组播/保留/未指定          │
              └─────────────┬───────────────┘
                            ▼ 安全
              ┌─────────────────────────────┐
              │ ② 熔断器（按 租户+工具 维度） │
              │   closed ──失败×5──► open    │
              │   open ──30s后─────► half_open│
              │   half_open 放行一次探测      │
              └─────────────┬───────────────┘
                            ▼ 允许
              ┌─────────────────────────────┐
              │ ③ 限流器（按租户维度）        │
              │   每秒 ≤ 20 次              │
              └─────────────┬───────────────┘
                            ▼ 未超
              ┌─────────────────────────────┐
              │ ④ 共享 httpx 连接池          │
              │   按 base_url 分池            │
              │   HTTP/2 + keep-alive 30s   │
              └─────────────┬───────────────┘
                            ▼
              ┌─────────────────────────────┐
              │ ⑤ 重试循环（最多2次）         │
              │   可重试：超时/连接错/5xx/429  │
              │   不重试：4xx/鉴权失败        │
              │   退避：0.5s → 1s           │
              └─────────────┬───────────────┘
                            ▼
              ┌─────────────────────────────┐
              │ ⑥ 响应裁剪到 8KB             │
              │   尝试美化 JSON              │
              └─────────────────────────────┘
```

**熔断/限流失败时的降级路径（不抛异常给 LLM）：**

```text
   工具调用失败
        │
        ├── 熔断打开?     ──► 返回 "工具当前不可用（服务熔断），请告知用户稍后重试"
        ├── 限流触发?      ──► 返回 "工具调用过于频繁，请稍后重试"
        ├── 连接超时?     ──► 返回 "工具调用失败：超时。请告知用户稍后重试"
        ├── 5xx / 429?   ──► 先重试2次，仍失败返回降级文本
        ├── 4xx / 401?    ──► 抛 ToolExecutionError（不重试）
        └── SSRF 拒绝?    ──► 返回 "工具地址不安全：xxx，请检查工具配置"
                              │
                              ▼
                    LLM 收到 observation 文本，
                    自己决定怎么回复用户（换话术/换工具/告知用户）
```

**SSRF 防护白名单/黑名单（DNS 解析后逐 IP 判断）：**

```text
   ┌─────────────────────────────┬──────────────────────────┐
   │ 允许（白名单）             │ 拒绝（黑名单）            │
   ├─────────────────────────────┼──────────────────────────┤
   │ 公网 IP（任意）             │ 127.0.0.0/8   loopback   │
   │ 10.0.0.0/8    租户内网     │ 169.254.0.0/16 链路本地   │
   │ 172.16.0.0/12 租户内网     │   └─ 含 169.254.169.254  │
   │ 192.168.0.0/16 租户内网    │      云元数据(拒绝)       │
   │                            │ 224.0.0.0/4   组播        │
   │                            │ 240.0.0.0/4   保留        │
   │                            │ 0.0.0.0/8     未指定      │
   │                            │ ::1 / ::      IPv6 同上   │
   └─────────────────────────────┴──────────────────────────┘
```

工具是统一资源的一类，在「资源管理」页维护：

1. 左侧菜单点「资源管理」→「新建资源」。
2. 抽屉中类型选「工具」，填名称；连接参数写在 `config`（JSON）中，HTTP 工具填 `method`、`url` 等。
3. 平台级工具保存后，在资源详情中授权给租户；租户管理员再在「角色管理」的角色详情中按角色授权（角色级工具授权体系保留）。画布的 HTTP / 插件调用节点只列出当前账号角色可见的工具。
4. 工具也可直接归属到租户（租户私有），仅本租户可见。

#### 工具治理默认值（一般不用改）

| 配置项 | 默认值 | 大白话 |
|--------|--------|--------|
| 连接超时 | 5 秒 | TCP 建连最多等 5 秒 |
| 读超时 | 30 秒 | 对方响应最多等 30 秒 |
| 整体超时 | 45 秒 | 从发请求到收完最多 45 秒 |
| 重试次数 | 2 次 | 超时/5xx/429 自动重试，退避 0.5s→1s |
| 熔断阈值 | 5 次 | 连续失败 5 次就"跳闸"30 秒 |
| 限流 | 20 QPS | 每租户每秒最多 20 次工具调用 |
| 响应裁剪 | 8 KB | 返回文本超 8KB 自动截断，防 prompt 爆炸 |

> **熔断/限流时会发生什么？** 平台**不会**把异常抛给 LLM 主循环，而是返回一句中文提示（比如"工具当前不可用（服务熔断），请告知用户稍后重试"），LLM 看到这句话后自己决定怎么回复用户——应用不会整个崩掉。
